Components

Use these documented components as a consistent starting point. Follow each component behavior, state, and accessibility guidance.

04 · Components

Buttons

Buttons perform actions; contextual text links navigate. Start button labels with a verb, use uppercase styling, and follow the action hierarchy.

Primary actions

Orange submits a form; blue is the primary non-submit action

One per page
A product page should have one primary action. Orange is for form submission; blue is for a primary action that does not submit.

Secondary & tertiary

Supporting actions with lower emphasis

Secondary
Outline buttons support secondary or equal-priority actions. Flat buttons suit cancel, reset, and exit.

Destructive action

Use red when an action cannot be undone

Destructive
Name the consequence clearly. Ask for confirmation when appropriate.

Disabled state

Explain what is needed to continue

Disabled
Complete required fields
Disabled controls should remain understandable and perceivable.

Sizes & inverse

Size changes preserve hierarchy and comfortable hit areas

Small · default · large
For dark brand surfaces only
Use the smallest size only where space is constrained; keep touch targets at least 44 × 44 px where practical.

Icon buttons

Pair icon-only controls with an accessible name

44 px target
An icon should reinforce a verb label when there is room. Never leave an icon-only button unnamed.

Multiple form actions

Reserve the solid orange treatment for one submission action

Use sparingly
Use orange outline only when multiple forms must submit on one page. If several forms compete, reconsider the page structure.

Button anatomy and language

Keep the action clear before adding visual treatment

DoUse a verb and name the result: “Find a doctor,” “Save changes.”
AvoidVague labels and navigation labels such as “Submit,” “Click here,” or “Learn more.” Use a contextual link label that says where it goes.

Forms

Labels stay visible, errors identify the field and the fix, and password visibility can be toggled when helpful.

Password field

Masked by default on every device

Error state

Explain what is wrong and how to correct it

Error

Enter the 9-digit member ID shown on your card.

Password creation guidance

Show requirements on focus in a create-account flow

  • At least 8 characters
  • One lowercase and one uppercase letter
  • One number and one special character
Password behavior needs Security sign-offThe legacy example proposes showing passwords by default on mobile. This preview uses masked-by-default behavior on all devices, with an explicit show/hide action, until Security confirms the product rule. Login screens should not show account-creation password rules.
